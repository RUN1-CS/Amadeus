# Security Policy

Security is an important part of Amadeus. We appreciate responsible security research and reports that help keep the project and its users safe.

## Supported Versions

Security fixes are primarily provided for the latest version of Amadeus.

Older releases may not receive security updates. Users are encouraged to upgrade to the latest available version.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues or Pull Requests.**

If you discover a potential security vulnerability, report it privately through one of the following channels:

- GitHub Private Vulnerability Reporting (preferred).
- Direct contact with the repository maintainer through GitHub.

When submitting a report, please include:

- A clear description of the vulnerability.
- The affected component or version.
- The potential security impact.
- Steps to reproduce the issue, where applicable.
- Relevant logs, screenshots, or other supporting information.

Please avoid including actual credentials, API keys, personal information, or other sensitive data in your report.

## Response Process

After receiving a report, the maintainer will:

1. Acknowledge receipt of the report.
2. Investigate and attempt to reproduce the vulnerability.
3. Assess its severity and potential impact.
4. Develop and test an appropriate fix.
5. Coordinate disclosure once the vulnerability has been addressed.

Response times may vary depending on the complexity and severity of the issue.

## Scope

Security reports concerning the following areas are particularly relevant:

- Authentication and authorization.
- Session management and account security.
- API endpoints and backend services.
- Database access and data isolation.
- File uploads, document processing, and local file access.
- Local LLM integrations and model interaction.
- Docker configuration and deployment security.
- Exposure of credentials, tokens, or other sensitive information.
- Dependency vulnerabilities affecting Amadeus.

## Responsible Disclosure

Please give the maintainer a reasonable opportunity to investigate and address a reported vulnerability before making it public.

Do not access, modify, or disclose other users' data without explicit authorization.

Do not perform destructive testing or disrupt services used by other people.

We appreciate everyone who helps make Amadeus safer.
